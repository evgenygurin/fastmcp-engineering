# Engineering Governance Acceptance Criteria

- [ ] Existing skills are mapped and dependencies/conflicts identified.
- [ ] Change-risk classification is explicit.
- [ ] Required gates are selected proportionally to risk.
- [ ] Version-sensitive claims have current authoritative evidence.
- [ ] Architectural changes require design approval.
- [ ] Breaking changes include compatibility, migration and rollback analysis.
- [ ] Verification evidence uses exact commands/checks and outcomes.
- [ ] Security/performance/reliability gates cannot be silently weakened.
- [ ] Exceptions record rule, reason, risk, compensating control, owner and expiry.
- [ ] Consequential decisions have ADR/decision records.
- [ ] Definition of Ready is explicit.
- [ ] Definition of Done is explicit.
- [ ] PRs document intent, evidence, verification and residual risk.
- [ ] Shared-state writes remain sequential and SHA-safe.
- [ ] Post-merge verification is performed when operationally relevant.
- [ ] Final governance audit can detect skipped or stale controls.
- [ ] Governance remains proportional and does not add ceremony without value.
