# Observability / Telemetry Acceptance Criteria

- [ ] Exact Python/FastMCP/OpenTelemetry/SQLAlchemy/PydanticAI/exporter versions identified.
- [ ] Current official OpenTelemetry and framework documentation reviewed.
- [ ] Instrumentation boundaries are explicit and domain remains telemetry-independent.
- [ ] MCP invocation telemetry uses stable, bounded attributes.
- [ ] DB telemetry does not expose sensitive bind values.
- [ ] LLM telemetry does not expose prompts/model output by default.
- [ ] Structured logs have stable event names and fields.
- [ ] Async trace/correlation context propagation is verified.
- [ ] Metrics use low-cardinality labels with an explicit budget.
- [ ] Sampling policy is explicit.
- [ ] Redaction occurs before export where practical and is tested.
- [ ] Exporter failure/backpressure cannot fail business operations.
- [ ] Shutdown/flush is bounded and tested.
- [ ] Liveness and readiness are distinct.
- [ ] User-visible SLIs/SLOs are defined where applicable.
- [ ] Telemetry retention/access/privacy boundaries are documented.
- [ ] Duplicate automatic/manual instrumentation is ruled out.
- [ ] Negative tests prove sensitive data is absent.
- [ ] Current official documentation is re-checked before completion.
